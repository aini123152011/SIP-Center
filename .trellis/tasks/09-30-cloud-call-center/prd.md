# 云呼叫中心与电销系统

## Goal

自研一套「电销驱动的交易闭环」云呼叫中心 + 电销系统：语音核心、AI 全量能力（机器人/实时转写/质检）、外呼调度、完整业务套件（客户/产品/订单/物流/财务），以 SaaS 多租户与私有化交付双形态对外。

## Background

- 全新仓库（greenfield），无既有代码与技术栈约束；仓库名 `SIP-Center` 印证自建语音核心路线。
- 部署目标中国大陆，电信合规（线路资质、实名、防骚扰频控）为硬约束。
- 需求经 2026-09-30 brainstorm 会话收敛，8 项关键决策全部拍板，开源选型调研见 `research.md`。

## Key Decisions

- **D1 产品形态**：SaaS 多租户 + 私有化交付，一套代码两种交付；私有化为单租户实例部署但 `tenant_id` 保留（防分叉）。SaaS 侧需计费/套餐/配额；私有化侧需部署物料/安装升级/License。线路模型可配置（SaaS=平台线路池分配；私有化=客户自带 SIP 中继，网关配置管理员可录）。
- **D2 AI 全量进 MVP**：智能质检 + 实时转写/坐席辅助 + 外呼机器人三者均为一期范围；实时媒体流管道为一期必选架构；机器人支持可编排话术 + LLM 兜底 + 打断；端到端延迟目标 P90 ≤1.5s。
- **D3 语音核心 = 自研 FreeSWITCH**（由 D1 推导）：云厂商呼叫 API 与私有化交付不兼容，混合路线造成双代码路径。
- **D4 后端主语言 = Java**；选型 Spring Boot 4 + MyBatis-Plus + Netty（ESL 自实现）+ PG/Redis/Kafka；前端 Vue3 + TypeScript + Ant Design Vue（随 JeecgBoot 而定，覆盖早期 React 提案）。
- **D5 外呼模式全量进 MVP**：手动点击 / 预览式 / progressive 倍率拨号 / predictive 预测式；dialer 策略可插拔；弃呼率为可配置硬指标（监管红线）。
- **D6 业务套件完整自研**：客户（含公海/名单分配）、产品、订单（电话成交弹屏联动）、物流（快递聚合对接）、财务（收款/退款/对账 + 开票）。业务域与语音域必须模块边界拆分。
- **D7 构建路线 = 自研核心 + 开源组件组合，业务/平台域骨架 JeecgBoot**（Apache-2.0 已核实）：JeecgBoot 仅承载平台域与业务域管理面；交易域核心手写禁低代码生成；语音域与 JeecgBoot 运行时零耦合。已接受前提：多租户深度自研补齐（M0 PoC 验证）、JimuReport/JimuBI 再分发条款核查、安全加固基线、fork 锁版本。
- **D8 团队与节奏 = 上限档 10+ 人并行**（语音 2/后端 4/前端 2/AI 2/测试运维 1）；里程碑 M1-M4 部分并行（M2 尾部与 M1 重叠、M3 管道自 M1 后期启动），总工期目标 ~6 个月；业务域保持 JeecgBoot 单应用 + 三部署单元（语音/业务/AI）并行，不上微服务。

## Requirements

**A. 语音域（voice-plane）**
- A1 呼叫控制：FreeSWITCH 之上的排队/ACD（技能组路由）、IVR（DSL 引擎）、转接/保持/三方、坐席状态机
- A2 外呼调度器：四模式策略可插拔，compliance 强制前置过滤（黑名单/频控/投诉名单，策略不可绕过）
- A3 线路接入：SIP 中继网关可配置；平台线路池按租户分配 / 私有化客户自带中继
- A4 录音与话单：全量录音入对象存储，CDR 落库，通话事件流（Kafka，按租户分 topic）
- A5 软电话：浏览器 WebRTC（JsSIP+WSS）自研组件，点击外呼/弹屏/通话中操作

**B. AI 域（ai-plane）**
- B1 实时媒体流管道：FS 媒体外送 → 实时 ASR（延迟预算 P90 ≤1.5s）
- B2 外呼机器人：话术 DSL 编排（版本发布/沙箱）+ LLM 兜底 + barge-in + 转人工上下文携带
- B3 实时转写与坐席辅助：通话字幕、话术推荐 v1
- B4 智能质检：离线转写 + LLM 评分/违规检测 + 质检任务与申诉流

**C. 业务域（biz-plane）**
- C1 客户管理：档案/联系人/跟进记录/名单导入分配/公海回收
- C2 产品管理：商品/价格体系
- C3 订单管理：电话成交弹屏下单、状态机流转（created→paid→shipped→signed→settled/售后）
- C4 物流：快递100/快递鸟聚合（运单/轨迹/电子面单）
- C5 财务：收款/退款/对账 + 开票对接（金税）

**D. 平台域（biz-plane 内）**
- D1 多租户：数据/线路/号码/配额隔离，`tenant_id` 进所有 schema 并入索引
- D2 SaaS 计费：套餐/配额/账单（通话分钟/坐席数/线路维度）
- D3 私有化交付：compose 拓扑（1 台/3 台）、安装升级脚本、License 机器码绑定离线激活
- D4 合规：黑名单/频控/投诉名单/录音留存策略
- D5 基础设施：PostgreSQL/Redis/Kafka/对象存储/Prometheus+Grafana

## Acceptance Criteria

- [ ] M1：新坐席登录工作台 10 秒内完成签入并接听经 IVR/ACD 分配的来电；全程录音可在系统内检索回放
- [ ] M1：200 并发压测 30 分钟，丢话率 0，无 OOM/重启，语音质量达标（MOS ≥3.8）
- [ ] M2：导入 1000 名单启动 progressive 任务，接通呼叫 5 秒内分配至空闲坐席并弹屏
- [ ] M2：predictive 外呼运行 1 小时，弃呼率 ≤ 配置阈值（默认 3%），坐席占用率报表可查
- [ ] M2：坐席弹屏下单，订单按状态机流转且全程可审计
- [ ] M3：机器人通话端到端应答延迟 P90 ≤1.5s，3 次以内打断不串话；转人工后坐席可见完整对话历史与实时字幕
- [ ] M3：100 条历史录音质检跑通，生成评分与违规标记，申诉-复检闭环
- [ ] M4：全新 Ubuntu VM 安装脚本 ≤30 分钟出可用实例；License 离线激活生效，超期/超配额正确降级
- [ ] M4：SaaS 租户全流程（创建→套餐分配→通话→账单）金额与计费规则一致
- [ ] 全局：租户 A 的任何数据/录音/报表在租户 B 登录下不可见（越权用例通过）

## Out of Scope

- 视频客服/视频外呼
- 完整工单系统（M4 后评估）
- 运营商线路资质自申办（商务路径落实）
- 多语言/多区域部署（v1 中文大陆）
- 原生移动 App（uniapp 后置评估）
- 全面微服务化（保留 JeecgBoot 微服务切换预案，v1 不实施）
